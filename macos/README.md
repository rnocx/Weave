# Weave for macOS

A thin native shell around the web app. The Xcode project **references**
`../index.html`, `../weave.css` and `../weave.js` in place (nothing is copied
into `macos/`), so there is one copy of the UI and both versions build from it.

## Build and run

Needs Xcode 15+ and [XcodeGen](https://github.com/yonaskolb/XcodeGen)
(`brew install xcodegen`).

```sh
cd macos
xcodegen generate          # writes Weave.xcodeproj (git-ignored); rerun after editing project.yml
open Weave.xcodeproj       # then ⌘R
# or from the command line:
xcodebuild -project Weave.xcodeproj -scheme Weave -configuration Debug -derivedDataPath build build
```

## Working on both at once

- **Debug builds load the web files straight from the repo root**, not from the
  bundle. Edit `weave.js` / `weave.css` / `index.html`, then press **⌘R** in the
  app (or reload the browser tab): no rebuild. Debug is unsandboxed to allow this.
- **Release builds bundle the three files** and are sandboxed.
- `deploy/build-public.sh` is unaffected: it only touches the three web files,
  and `macos/` is not part of `weave.zip`.
- The web app must keep working in a plain browser. Native features are added
  from outside it (`Weave/NativeBridge.js` is injected at page start), so
  `weave.js` has no Mac-specific code. If you need one, feature-detect it.

## What the shell adds

| Feature | How |
|---|---|
| Page served as `weave://app/` | `AppSchemeHandler`: a secure context, so `crypto.subtle` (hashed login) works |
| Unified title bar, translucent sidebar | `MainWindow.swift` (full-size content view + vibrancy view behind a transparent `WKWebView`); `Weave/mac.css` restyles the page, scoped under `.native-mac` |
| Native menus and shortcuts | `WeaveApp.swift`: ⌘, Settings, Go menu (⌘K, ⌥↑/↓, ⌥A, ⇧⎋), Find (⌘F), member list, reload and zoom. They drive the page through `window.__weaveMacAction` |
| Window drag and double-click zoom | the page's top bars post a message; `MainWindow` calls `performDrag` |
| Theme-aware window | the page's chosen light/dark theme is mirrored into `NSWindow.appearance` |
| macOS accent colour | a "system" swatch is added to Settings → Accent and follows System Settings |
| Close hides, app keeps running | the relay connection and notifications stay alive; Dock click or a notification brings the window back. ⌘Q quits |
| System notifications | `Notification` is replaced with a shim → `UNUserNotificationCenter`; clicking one focuses the buffer |
| Dock badge | the unread-mention count parsed from the page title `(N) …` |
| Links open in the default browser | navigation + `target=_blank` interception |
| Password in the Keychain | `Keychain.swift`; the page uses it through `window.__weaveSecrets` (NativeBridge.js). A password saved by an older version is moved out of `localStorage` on first launch |
| Self-signed relay certificates | `CertTrust.swift`: trust on first use. Shows the SHA-256 fingerprint once, pins it per host:port, warns if it changes. File → Forget Trusted Certificates resets |
| Command palette in the menu | Go → Command Palette… (⇧⌘P) |
| 📎 file picker, alerts | `WKUIDelegate` |

`NativeBridge.js` (behaviour) and `mac.css` (look) are the only places Mac-specific
page code lives. In Debug, `mac.css` is also read live from `macos/Weave/`.

Debug-only helpers: `WEAVE_DEBUG_JS="<js>"` runs a script after load and logs the
result; `WEAVE_SNAPSHOT=/path.png` writes a PNG of the page.

## Known gaps (follow-ups)

- **Uploads still need CORS.** The page origin is `weave://app`, so a Jirafeau
  server needs `Access-Control-Allow-Origin: *` (as for `file://`; see the main
  README). A native fetch bridge would remove that.
- **Not yet verified by eye:** the vibrancy blend of the sidebar over each theme, and hide-on-close / Dock reopen. Check both after a fresh build.
- **Relay `websocket_allowed_origins`**, if you set it, must also allow
  `^weave://app$`.
- **Keychain prompt after a rebuild.** With ad-hoc signing every build is a new
  code identity, so the first read after a rebuild asks for your login password
  ("Always Allow" fixes it until the next build). Signing with a team ID ends this.
- **Pinned certificates** live in the app's preferences; `defaults` reads the
  sandboxed (Release) copy, so for a Debug build use
  `defaults … ~/Library/Preferences/me.interdo.weave`.
- **Distribution:** set `DEVELOPMENT_TEAM` in `project.yml`, then archive, sign
  and notarize. The icon is generated by `tools/make-icon.swift` (squircle, gradient, bolder W) from the same
  geometry as the web logo.
